01 The Problem in Plain English

Every engineer has an AI assistant.
None of them share what they learn.

In May 2026, a typical mid-size software company has rolled out AI coding assistants to its engineers. Tools like Claude Code, Cursor, Codex, and Gemini CLI. Every engineer has one. They use them every day. The problem is simple: every AI starts from zero.

When Alice teaches her AI assistant that the company's payment system has a quirk on Tuesdays, only Alice's AI knows that. When Bob runs into the same Tuesday quirk next week, his AI rediscovers it the hard way — by breaking something. The knowledge Alice taught her AI never reaches Bob's AI.

Multiply this across an entire engineering team and you get a company that's losing the knowledge its engineers teach their AIs every single day.

Today — each AI is alone
Five engineers. Five private notebooks. Knowledge stays trapped on individual laptops.
02 How Krimto Solves It

One shared notebook.
Every AI reads from it. Every AI writes to it.

Krimto is one shared brain that every AI at the company talks to. When Alice's AI learns something, Krimto writes it down. When Bob's AI needs to know something, it asks Krimto. The knowledge that used to stay on Alice's laptop now flows to everyone who needs it.

Setup is simple: the company runs Krimto on a single computer. Every engineer points their AI assistant at it with one config line. After that, every AI sees the same shared brain.

03 How Knowledge Is Organized

Not everything is shared with everyone.
Krimto has three layers.

If every AI at the company saw every piece of knowledge, the brain would be cluttered with everyone's personal preferences. Krimto solves this with three layers, from most specific to most general:

01
Personal
Only your AI sees these. Your preferences, your shortcuts, things specific to how you work.
"I like 4-space indents"
"My VPN is on Tuesdays only"
02
Team
Everyone on your team's AI sees these. How your team builds and tests things together.
"The payments team uses Stripe webhooks"
"We deploy on Wednesdays only"
03
Company
Every AI at the company sees these. Standards, conventions, security rules that apply to everyone.
"Never log customer email addresses"
"All passwords must be hashed with bcrypt"

How it works in practice

Alice asks her AI: "Help me set up a new payment endpoint."

The AI asks Krimto, in this order:

① Personal layer — does Alice have any personal preferences for this? (e.g., "I always write tests first") → Yes, apply that.

② Team layer — does the payments team have conventions? (e.g., "Use the Stripe webhook pattern") → Yes, apply that on top.

③ Company layer — does the company have rules? (e.g., "Never log customer email addresses") → Yes, apply that on top.

The result: The AI writes the endpoint using Alice's testing style, the team's Stripe pattern, and the company's security rules — all automatically. Alice never had to explain any of those three things.

04 Where The Knowledge Actually Lives

Plain text files. In a folder.
Edit with any text editor.

The most unusual thing about Krimto is that the knowledge isn't stored in a complicated database that only the software can read. It's stored as plain text files in a folder — the same way engineers already store their code.

This means: humans can read it. Humans can edit it. When something changes, you can see exactly what changed, who changed it, and when. There's no black box.

/company-knowledge/
├── personal/
│ ├── alice/preferences.md # Only Alice's AI sees
│ ├── bob/preferences.md
│ └── carol/preferences.md
├── teams/
│ ├── payments/
│ │ ├── stripe-conventions.md # All payments-team AIs see
│ │ └── deployment-rules.md
│ └── infrastructure/
│ └── on-call-procedures.md
└── company/
    ├── security-standards.md # Every AI at company sees
    ├── code-style.md
    └── api-conventions.md

The folder is tracked with git — the same system engineers use to track their code. So every change is recorded with timestamp, author, and reviewer. If someone writes a bad rule, you can roll it back. If you need to know who wrote a specific guideline, you can find out in seconds.

One important honest note: just storing facts in markdown files isn't enough by itself. At team scale, you also need a fast index to search them (because you can't grep through 100,000 facts in real-time), and you need a server that controls who can read what (because folder permissions alone aren't role-based access control). Krimto ships these as one package: markdown files for storage + a fast search index + a server that enforces access rules. This is the same hybrid pattern that Anthropic's Claude Code uses (CLAUDE.md system), that the memweave project verified in production (April 2026), and that successful AI agent systems Manus and OpenClaw have converged on independently. Pure files alone don't work at team scale — the hybrid pattern does.

05 The Three Layers — What Humans See, What AIs See

Git is the source of truth.
The API and the web interface sit on top.

A useful comparison: GitHub. The actual data lives in git — every file, every change, every history entry. But people don't usually use git from the command line. They use GitHub's website to browse code, review pull requests, manage permissions. The website doesn't replace git; it makes git easier to use for humans.

Krimto works the same way. The knowledge lives in markdown files in git. That's the source of truth. On top of that, Krimto has two more layers — one for AIs to talk to, and one for humans to browse.

01
The data layer (git)
Markdown files in a folder, tracked with git. This is where the knowledge actually lives. Anyone can open the files in a text editor. Every change is reviewed via pull request. This is the source of truth.
teams/payments/
stripe-conventions.md
(plain text file)
02
The API layer (for AIs)
A small server that AI assistants talk to. When an AI needs to read or write a fact, it calls this server. The server reads the right markdown file based on who's asking, and returns the answer. AIs never touch the files directly.
AI calls: /memory?scope=team
Server reads: teams/payments/...
Returns: the relevant facts
03
The web interface (for humans)
A dashboard in your browser. Browse facts across all three scopes. Search by keyword. See which facts are most-read or stale. Approve pull requests with one click. Manage who has access to what. Same data as the files; just easier to browse.
Open: krimto.acme.com
See: list of all facts
Click: approve, edit, search

The plain-English summary

You can manage Krimto two ways: open the markdown files in a text editor and commit changes via git (what engineers usually do), or open the web dashboard in your browser (what managers and reviewers usually do). Both ways edit the same data. Git is always the source of truth.

This is exactly how GitHub works. The data lives in git. You can do everything from the command line. But the website makes life easier. Krimto follows the same pattern.

Why this matters: every other memory tool (Mem0, Hindsight, Langfuse, ByteRover) also ships a web dashboard. Having one is table stakes, not a feature that makes Krimto different. What makes Krimto different is that underneath the dashboard, the data is markdown files in git — not a database that humans can't read directly.

07 The Three Things to Remember

If you forget everything else,
remember these three.

01

Krimto is one shared brain for every AI at the company

Not one brain per person. Not one brain per AI tool. One brain that every AI at the company can read from and write to. Built specifically for teams, not for individuals.

02

Knowledge is organized in three layers

Personal (only you), Team (your team), Company (everyone). When your AI asks a question, Krimto checks the most specific layer first, then broader. Like consulting your notebook, then your team's playbook, then the company handbook.

03

Hybrid storage: markdown files in git, with a fast index on top

The knowledge itself is plain text files in git — humans can read and edit them directly. On top sits a fast search index (so 100,000 facts can be searched in milliseconds), an API (so AIs can call it), and a web dashboard (so humans can browse). Pure files alone don't scale at team level — verified across Anthropic's Claude Code, memweave, Manus, and OpenClaw, the hybrid pattern is what actually works.

All nine other memory tools that exist today do something different on at least one of these three. None of them combine "shared across the company" + "three-layer hierarchy" + "plain text files in git" the way Krimto does. That combination is the open seat — verified against each competitor's published architecture documentation.
